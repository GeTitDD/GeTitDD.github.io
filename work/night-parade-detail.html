PROJECT CONTEXT / 项目背景与定位

用明确的提交边界，
支撑持续演化的互动叙事。

Night Parade 是一套独立设计的全栈 Multi-Agent 互动叙事与沙盒 RPG 世界引擎。系统将世界观创作、多角色权限隔离、CAS 事务一致性提交与分层长程记忆收敛于统一运行底座，重点解决长周期叙事中的状态撕裂与工具越权难题。

01 / STATE CONSISTENCY

叙述与机械状态可能分别成功。

单一对话流直接修改状态，容易把“剧情已显示”误当作“数值已落库”。项目区分叙述提案、规范校验和机械提交，以读取基线、CAS 与 SQLite 事务约束并发写入。

02 / LONG-RUN BOUNDARIES

历史记忆与在途对局各有边界。

长局需要客观记忆归档而非无限堆叠对话；作者热更新也不应静默污染已开局世界。Storybook 归档、冻结快照和显式同步分别处理记忆、版本与工具写入范围。

SYSTEM ARCHITECTURE / 系统架构

先界定事实归属，
再让角色协作与状态提交闭环。

职责与工具权限分离，提交由服务端统一校验。

主 GM 负责上下文装配、流式叙述与结构化状态提案；Pi 工具仅返回 Prepared Checkpoint 准备结果。完整回复通过校验且未取消后，由服务端提交机械状态。Luna 按作者草稿或本局副本的授权范围执行工具读写，并回读确认结果。

复用已生成结果，以 CAS 守住恢复边界。

叙述已保存而机械状态提交中断时，系统基于完整 Prepared Checkpoint 开放幂等恢复入口，复用准备结果并保持零额外模型调用。恢复前重新校验读取基线；发生 CAS 冲突时先读取现状，结果待确认时进入状态核验，避免覆盖并发编辑或重复提交。

显式发布与三向同步，隔离草稿和在途对局。

作者草稿、project_versions.snapshot 与 games.snapshot 分别承载编辑态、发布版本和冻结对局。三向同步比较基线、当前对局与作者草稿，按差异显式拉取或推送；私有回执、检查点与 GM Turn Trace 保持服务端权限隔离。

ENGINEERING DESIGN / 核心机制深潜

用工具契约和提交条件，
约束生成式系统的自由度。

01 / ROLE ORCHESTRATION

三角色编排，三种执行边界。

主 GM 装配规则、角色与当前状态、近期完整对话、世界检索、已有摘要与 Storybook 召回；依据模型窗口与配置执行 Token 预算分配和上下文裁剪。

Pi 后台维护在步骤与工具预算内准备演化队列结算与客观归档，以私有 Prepared Checkpoint 记录准备结果。Luna 通过范围受限的持久工具对话与子代理执行任务，写入后回读确认；不确定请求进入结果核验，避免盲目重发。

02 / STORYBOOK MEMORY

归档与合卷，不让记忆变成新指令。

第 8 回合触发客观 Scene 归档，每 10 个 Scene 合卷为 Chronicle 并建立标签索引。结构化场外召回保留精确引用，明确标记已归档客观记忆，避免历史事件再次结算。

超过 100 个活跃 Chronicle 索引时，通过显式 archive-band 执行分层维护，保留历史引用链。Storybook 客观记忆与助手持久聊天分别管理；长聊自动语义压缩与自动化归档调度纳入后续演进。

03 / SCOPED SKILLS & TOOLS

9 个 Skill，权限以具体上下文为准。

作者模式包含 20 个工具，对局模式包含 19 个。作者专属 gameStart 管理开局配置；批量 run 强制先执行 Dry-run，写入后回读确认，revert 由明确撤销指令触发。

图像生成、子代理和历史读取均绑定当前授权范围。作者草稿与玩家私有对局分别隔离，审计工具依据可访问的数据给出结果，跨角色访问通过服务端权限校验。

04 / GM TURN TRACE

真实来源、历史缺失与降级都应可辨认。

GM Turn Trace 持久化实际请求输入、Token 裁剪上下文与原始模型返回，/debug-turn 按 request ID 回溯诊断。历史快照缺失时标识 legacy 或不可用，保持输入、生成与状态提交的可追溯性。

界面分别呈现真实模型回复、离线兜底与部分回复，并将取消、提交冲突和恢复结果映射为明确状态，为运行诊断与多回合问题定位提供完整证据链。

Luna 的九个声明式领域入口

Skill适用范围

/build-map在获授权的作者世界或本局副本中制作地图。
/place-tokens按当前上下文放置角色、NPC 与怪物。
/feature-audit作者世界功能审计；对局内仅报告可验证局部范围。
/file-type-audit审查类型、字段与布局。
/instruction-audit审查 GM 指令，受上下文权限限制。

/fix-game检查与修复获授权的当前对局副本。

20 / 19 个工具是权限面，不是无限授权。

读取与诊断：read、list、search、readGameHistory、inspectGmTurn、viewImage；文件写入与撤销：write、update、files、revert；地图：map、linkedLocations；批量、脚本与类型：run、runScript、upgradeScript、editFileType；交互与代理：askUserQuestion、generateImage、spawnSubagents；作者模式额外包含 gameStart。
