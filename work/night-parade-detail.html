核心产品与 Multi-Agent 架构 / 2026

Night Parade（百鬼夜行）：确定性 Multi-Agent互动叙事与沙⁠盒 RPG 世界引擎

以本地重构与隔离验证为边界，拆解 Studio 创作、GM 叙事、Pi 后台维护与 Orbit 工具助手如何围绕规范校验、CAS 原子提交、冻结快照和 Storybook 长程记忆协作。重点验证世界运行秩序，而非把单一模型对话包装成完整游戏系统。

PROJECT CONTEXT / 项目背景与定位

用明确的提交边界，
支撑持续演化的互动叙事。

这是以 Night Parade 为重点世界的 Craft 公开体验本地重构实践。页面、业务数据与模型调用由独立实现承担，不使用 Craft 官方后端执行游戏；不宣称已完成所有世界、玩法组合或原站私有算法的等价复现。

01 / STATE CONSISTENCY

叙述与机械状态可能分别成功。

单一对话流直接修改状态，容易把“剧情已显示”误当作“数值已落库”。项目区分叙述提案、规范校验和机械提交，以读取基线、CAS 与 SQLite 事务约束并发写入。

02 / LONG-RUN BOUNDARIES

历史记忆与在途对局各有边界。

长局需要客观记忆归档而非无限堆叠对话；作者热更新也不应静默污染已开局世界。Storybook 归档、冻结快照和显式同步分别处理记忆、版本与工具写入范围。

当前交付是本地可体验系统与指定流程的隔离验收，不是对外生产部署证明。端口 3000 与 3011 代表两套隔离运行实例，不是两个业务微服务。

SYSTEM ARCHITECTURE / 系统架构

先界定事实归属，
再让角色协作与状态提交闭环。

职责分离不等于全都只读。

Pi 工具仅返回准备结果。主 GM 仍使用既有编排，在完整回复、未取消且校验通过后由服务端提交机械状态。Orbit 则按作者草稿或本局副本权限执行真实读写，三者不能混为同一写库流程。

恢复不重新生成，也不强行覆盖。

叙述已保存但机械提交失败时，界面明确提示。只有完整 checkpoint 才提供恢复入口；基线变化必须拒绝覆盖，结果不明先读现状。CAS 与事务保证指定提交的条件与原子性，不保证每次请求都成功。

发布、拉取、推送必须显式。

作者草稿、project_versions.snapshot 与 games.snapshot 分别归属不同阶段。三向同步比较基线、当前对局和作者草稿，不以整库替换代替同步。私有回执、checkpoint 与 GM trace 不应作为公开运行态原样下发。

六类规范 Owner：谁拥有哪一份事实。

Owner职责与不变量
Clock剧情日期与时间；设备时钟不能代替剧情推进。
World Pulse当前焦点、分辨率与加载领域；不维护第二份权威队列。
Runtime Ledger模拟队列、信号、事务记录与因果回执。
Current Scene当前段落暂存记录与已接受叙事回合计数。
Campaign LedgerScene、Chronicle 与标签索引。
Scene 与 Chronicle已归档客观记忆和精确引用，不作为自动新事件执行。
ENGINEERING DESIGN / 核心机制深潜

用工具契约和提交条件，
约束生成式系统的自由度。

01 / ROLE ORCHESTRATION

三角色编排，三种执行边界。

主 GM 装配规则、角色与当前状态、近期完整对话、世界检索、已有摘要与 Storybook 召回；预算由模型窗口和本地配置共同限制，不会固定发送全部世界。

Pi 后台维护按步骤与工具预算顺序调用工具，准备演化队列结算与客观归档，使用私有 checkpoint；失败不自动重发不确定请求。Orbit 保持范围受限的持久工具对话与子代理，写入后回读确认。

02 / STORYBOOK MEMORY

归档与合卷，不让记忆变成新指令。

第 8 回合触发客观 Scene 归档，每 10 个 Scene 合卷为 Chronicle 并建立标签索引。结构化场外召回保留精确引用，明确标记“已归档客观记忆”，避免历史事件再次结算。

超过 100 个活跃 Chronicle 索引时需要显式 archive-band 分层维护，不静默丢弃历史。助手持久聊天与上下文预算已有实现，但长聊自动语义压缩尚未完成，不能与 Storybook 合卷能力混为一谈。

03 / SCOPED SKILLS & TOOLS

9 个 Skill，权限以具体上下文为准。

作者模式包含 20 个工具，对局模式包含 19 个。额外的 gameStart 用于读取或修改开局配置，不负责启动游戏；run 必须先预演，revert 需要明确撤销指令，问题工具等待真实回答。

图片与子代理受设置和授权范围限制；作者不能越权读取其他玩家的私有对局历史。Skill 已注册不代表所有官方细节已等价复现，游戏内审计只能报告当前权限下可验证的局部范围。

04 / GM TURN TRACE

真实来源、历史缺失与降级都应可辨认。

GM Turn Trace 保留实际请求输入、Token 裁剪上下文与原始模型返回，/debug-turn 按 request ID 诊断已有记录。旧存档缺少历史快照或 trace 时，明确标识 legacy、损坏或不可用，不据现有状态伪造历史输入。

UI 区分真实模型回复、离线兜底与部分回复。指定真实供应商记录只证明对应流程；深层世界演化的通用语义、私有算法等价及真实长局组合仍需要进一步验证。

Orbit 的九个声明式领域入口

Skill适用范围
/build-world从空作者项目搭建世界；不直接覆盖已有项目。
/build-map在获授权的作者世界或本局副本中制作地图。
/place-tokens按当前上下文放置角色、NPC 与怪物。
/feature-audit作者世界功能审计；对局内仅报告可验证局部范围。
/file-type-audit审查类型、字段与布局。
/instruction-audit审查 GM 指令，受上下文权限限制。
/map-audit审查地点、连接与旅行时间。
/fix-game检查与修复获授权的当前对局副本。
/debug-turn按 request ID 读取获授权且已保留的真实 GM trace。

20 / 19 个工具是权限面，不是无限授权。

读取与诊断：read、list、search、readGameHistory、inspectGmTurn、viewImage；文件写入与撤销：write、update、files、revert；地图：map、linkedLocations；批量、脚本与类型：run、runScript、upgradeScript、editFileType；交互与代理：askUserQuestion、generateImage、spawnSubagents；作者模式额外包含 gameStart。

04 / REAL BROWSER

27项检查通过

真实已保存档案与运行态检查，另有 1536 / 390 / 320 视口截图目检。

并非与原站每个同状态画面的逐像素等价证明。

94 的组成：67 项源码检查 + 27 项真实浏览器检查。

33 + 16 + 18 = 67；再加 27 项真实浏览器检查，共 94 项跨层记录。它们不是同一次执行的统一测试套件，也不代表全站完成率。

另行记录：模拟档案与运行态面板 31 项、模拟恢复交互 28 项；真实供应商共 16 次文字尝试（6 次 GM 请求 + 10 次 Pi 步骤）；当时 TypeScript 全量 noEmit 退出码为 0。以上不同证据不重复加总到 94。

尚未证明或仍需继续实现的边界

  • 深层演化的未知自然语言条件保持 Pending，私有 LWE 算法等价尚未证明。
  • 本地角色创建只执行 cover、choice、longText 等指定子集；部分高级配置返回 unsupported。
  • 助手长聊自动语义压缩、通用 Script API v2 的全面兼容与真实超长战役仍待补充。
  • 官方 BGM / SFX 与全部原站媒体未完整取得；当前为本地合成氛围音，不能宣称官方音画已等价复现。
  • 本地登录与会话属于开发复刻实现，不构成生产身份安全方案。
  • 隔离实例 3011 的验收不能外推到原有 3000 构建、所有世界、所有脚本及未来运行组合。
