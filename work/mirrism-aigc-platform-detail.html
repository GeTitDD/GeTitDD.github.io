SYSTEM ARCHITECTURE / 系统架构

先厘清系统信任边界，
再贯通异步创作链路。

架构核心目标是将“参考图语义检索、多模态 Agent 编排、Flow 节点工作流、长耗时渲染与资产归档”收敛于同一条可追溯管线；并通过物理与逻辑解耦，将高频交互请求、重度异步任务与外部不可靠模型 I/O 彻底隔离。

围绕这一独立全栈构建并上线的生产级多模态平台，我主导了从产品定义、Design Engineering 交互体系、21 服务容器化编排架构到线上性能治理的端到端交付。

核心角色：产品定义 / Design Engineering 交互 / 全栈架构与分布式调度 / 性能压测与交付

系统职责分层

  1. 01 / EXPERIENCE

    体验层

    React 19 三屏工作台，统一承接虚拟化灵感图库、Agent 协同对话与原生 SVG Flow 节点画布。

  2. 02 / GATEWAY

    网关层

    Nginx 负责 HTTPS 卸载与短期签名媒体 Relay；DispatchLane 动态决策模型路由，由 New API 统一收敛多供应商调用。

  3. 03 / BUSINESS

    业务层

    Django API 集中管控领域规则、RBAC 权限校验、额度预扣/退回原子事务及全生命周期任务审计。

  4. 04 / AGENT

    Agent 运行层

    独立 Pi Agent Node.js 进程接管多轮推理与工具编排，通过绑定租约凭证的私有回调与主业务安全同步事件。

  5. 05 / WORKERS

    异步执行层

    PostgreSQL Skip-Locked 队列与 Celery Worker 异步消费长耗时任务；内置 ElasticSupervisor 感知主机负载动态伸缩并发槽。

  6. 06 / DATA

    数据与资产层

    PostgreSQL 17 保障核心事务与任务状态一致性，Redis 7 支撑高速缓存与消息分发，私有 S3/OSS 分层托管原图与多级 WebP 派生资产。

注：上方卡片按「逻辑职责」划分为六层；下方工程图则按「实际物理进程与容器编排边界」展开为四层拓扑，两种视图互为补充。

21 服务容器化物理隔离

以 21 服务容器化编排落实进程与职责隔离，按 01 Client & Edge、02 Business & Data、03 Runtimes 与 04 Model I/O 四层展开：三屏工作台与 Nginx、Django 与数据底座、独立 Pi Agent 与图像 Worker、DispatchLane 控制面与 New API 网关各司其职。

PostgreSQL 短事务队列与资源感知

通过 FOR UPDATE SKIP LOCKED 短事务队列原子领取任务，出网等待前释放非事务数据库连接，避免长耗时模型调用占住连接池；ElasticSupervisor 感知主机 CPU、可用内存、Swap 增长及上游余量，动态收紧或释放 Worker 并发槽位。

部署边界：ElasticSupervisor 位于图像业务 Worker 内，Coordinator 独立运行；DispatchPool 表示逻辑模型，不是另一个独立服务。

发送边界不变量

超时分支遵循 queued → reserved → started → uncertain：越过发送边界进入 started 后发生超时，冻结为待核实态（Pending Reconciliation），严禁盲目重试付费请求；正常完成仍归入 succeeded / failed。只有确认 cancelled、not_sent 且 started_at 为空的过期预留，才允许安全重分配。

Result Checkpoint 字节优先落盘

供应商返回图像字节后，先写入确定路径的图像字节与元数据 Checkpoint，再执行原图 / 预览存储及资产归档。下游副作用异常时，复用已持久化的图像字节恢复交付，不重新请求供应商，保护已经付费取得的结果。

恢复边界：Checkpoint 属于 best effort，写入失败不会阻断普通结果交付；恢复依赖已经持久化的记录与文件，不承诺断电场景零丢失。

300ms 游标事件流合并持久化

独立 Pi Agent 流式处理工具决策与澄清，约每 300ms 合并事件并持久化至 Django 事件序列；前端通过 GET turns/{id}/?after=<seq> 游标增量读取，在上一轮请求结束后约 900ms 再次轮询，兼顾连续反馈与页面刷新恢复。

UUID5 幂等 HITL 审批闭环

HITL 默认开启，也可配置关闭。模型触发 generate_image 时，以 UUID5(turn.pk, tool_call_id) 派生幂等审批 ID 并挂起确认卡片；用户确认后执行服务端二次重报价、账户 / 会话锁与积分幂等事务，再完成扣费和任务派发。模型提议 ≠ 自动扣费。

时序边界：300ms 与 900ms 为事件合并与轮询节奏，不是实时性 SLA；审批 ID、服务端重报价与事务幂等共同约束付费边界。

ENGINEERING DESIGN / 关键实现

将多模态工作流、向量检索与端侧交互，
收敛为确定性的系统机制。

/ 1

异构 Agent 运行时与安全边界

将 Agent 推理拆分为独立 Node.js 服务（基于 Pi Agent Core），与 Django 主业务物理隔离。Agent 仅获取服务端动态授予的工具权限（后端二次校验），私有工具回调绑定单次 turn 与 30 分钟动态续租凭证，过期或取消即刻失效。

/ 2

确定性工作流编译（M0–M3 / 换装 / 姿势）

针对多轮局部编辑中的角色身份漂移，通过 ElementRevision 版本快照锁定与结构化提示词编译，固定角色元素、输入图片序号和场景模式。工作流适配器覆盖 M0–M3、换装与姿势编辑，以 prompt_adaptation / pose-compiler 将创作意图编译为强约束指令，减少纯文本拼接与反复编辑造成的身份偏移。

/ 3

“随机种子”多阶段检索与防退化管线

以 本地只读 mmap + NumPy 内存映射检索替代对重型外部向量数据库的依赖，减少远程调用成本：VLM 图像事实分析 → 构造查询向量 → 归一化点积检索 Top64 → 滑动窗口历史降权（近 20 次使用统计、半衰期 5 次）→ 多候选送入 Writer 编译 → 异步生图，在低成本本地召回中兼顾创意发散与重复抑制。

/ 1

多供应商统一网关与精准能力路由

自建 DispatchLane / Pool 逻辑控制面（划分 analysis / image / embedding 三条独立通道）协同 New API 传输网关，按精确模型、质量档位、视觉能力、池占用与冷却状态进行选路，并在出站边界完成特定供应商的 MIME 校验与 WebP 无损转 PNG 适配。

/ 2

离线推荐预计算与原子发布

读写分离与离线预计算管线：通过数据库租约与原子发布指针切换推荐快照，彻底剥离高并发浏览路径上的实时重计算，同时保留实时权限校验与幂等访问记账。

/ 3

全链路资产追溯与版本快照

引入 ElementRevision 元素版本快照机制（支持 latest / standard / fixed 引用策略），确保历史任务不因后续元素修改而失真；所有生成成果按任务来源去重归档至 Project 与账户共享资产库，支持跨会话复用与二次迭代。

/ 1

三屏联动工作台与跨屏身份拖拽

摒弃频繁跳页的传统表单，构建资源、创作与 Flow 画布三屏协作空间（支持拖拽调宽、键盘控制与收纳状态无障碍隔离）。设计自定义 MIME 协议（application/x-mirrism-resource+json），跨屏拖拽时完整携带 referenceId、storageKey 与 sourceTask 身份信息。

/ 2

多图编号与 @元素 内联引用组件

针对多图参考场景下“哪个人、哪件衣服、哪张背景”的指代难题，开发不可拆分的富文本内联引用（Inline Chip），支持 @ 唤起元素版本选择器与点击图片编号快速插入引用，显著降低提示词编写的认知负荷。

/ 3

浏览器端 GPU 实时调色与虚拟化长流

将图像调色下沉至客户端：基于 Oklab 色彩空间统计 + 33³ 3D LUT + WebGL2 Fragment Shader 实现零后端开销的实时调色与前后对比；对话流采用 TanStack Virtual 动态测量虚拟化，保障长上下文图文混排的流畅滚动。

“零后端开销”仅指浏览器内的本地调色处理；平台服务、模型调用与图像生成仍使用后端及供应商资源。

/01 · FINANCIAL-GRADE IDEMPOTENCY

UUID5 · uncertain · Result Checkpoint

审批幂等标识 · 越界超时冻结 · 图像字节优先落盘

严格界定异步发送边界：越界超时转入待核实态，禁止盲目重发付费请求；恢复时复用已持久化图像字节，避免重复消耗资金与供应商算力。

0 重复扣费与 100% 幂等闭环为机制设计目标，不代表已审计的生产零事故或覆盖率统计；Checkpoint 恢复以已落盘记录为前提。

WebGL2 · 33³ 3D LUT

Oklab 色彩空间转换与 LUT 调色由 Fragment Shader 执行。

架构复盘 / 核心工程价值的三个落点

全链路可追溯的付费生成状态机

将 PostgreSQL 事务记录、供应商租约栅栏（Lease & Fencing）与分段 Checkpoint 串联为闭环恢复路径——越过发送边界超时自动转入待核实态，避免盲目重发带来的重复扣费，并为已持久化的生图结果保留恢复入口。

主机资源感知的自适应并发控制

内置 ElasticSupervisor 实时监测主机 CPU、可用内存、Swap 增长率及上游通道余量，动态收紧或释放 Worker 执行槽位；在同规格 4 vCPU / 4 GiB 隔离副本中验证高负载主动排空与零 OOM 崩溃。

零摩擦的 Design Engineering 创作体验

Design Engineering 交互：三屏联动工作台、自定义 MIME 跨屏资产拖拽、@元素版本快照内联引用及 WebGL2 33³ LUT 浏览器端实时调色。

口径说明：机制设计约束、交互目标、生产配对测试与受控隔离压测分别标注。受控模拟上游基准不代表真实供应商生产容量，也不构成所有任务零失败的保证。
