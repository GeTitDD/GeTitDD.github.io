Aurora Alpha：基于 CEGIS 的量化语义编译工作台

交易文献与盘面经验中的模糊条件、隐含时序，容易在代码实现中被误读。项目以明确的语义契约约束候选，沿 CEGIS 反例反馈持续修订，将知识沉淀为可复核、可复用的量化研究模块。

PROJECT / 项目定位

将模糊的交易经验，
编译为可检验的语义。

Aurora Alpha 面向个人量化研究中的交易语义开发。金融文献与经验描述往往省略适用条件和信息时点，直接转写指标代码时，可能引入含义偏差与前视风险（Look-ahead Bias）。工作台将概念拆为可组合的“语义积木”（Semantic Bricks），关联来源、定义、候选实现与验证记录。

研发遵循“先明确含义，再约束实现，以反例推动修订”：界定概念适用环境、前置依赖和事件先后关系，再借鉴 CEGIS 循环核对候选与预期语义。语义约束检查与历史场景复核各有职责，共同为下一轮修订提供依据。

SYSTEM ARCHITECTURE / 系统架构

解耦四大核心职责，
贯通语义研发闭环。

按研究职责分为研究入口、语义研发、验证工具与模块资产四个部分：入口承接材料和问题，语义研发组织定义与候选，工具支持检查和复核，模块资产保留经确认的研究成果。

协作以同一研究问题及其版本引用为线索：会话接续讨论，语义契约限定候选边界，图表与回放提供观察入口，模块版本关联采用依据与验证记录。

研究入口 / 保留问题上下文。

以研究会话承接来源材料、当前解释和待确认问题，使概念界定、候选实现与后续验证能够接续；来源证据与研究推断分别保留。

语义研发 / 组织定义与候选。

将交易概念、输入依赖、适用条件与事件关系表达为语义约束，围绕已明确的含义构建候选，并将验证偏差定位到需要修订的定义或实现。

验证工具 / 连接实现与证据。

指标与计算工具提供可复用的实现能力；行情图表、历史回放和手动模拟帮助观察具体场景中的指标表现，为条件边界与事件顺序提供复核依据。

模块资产 / 保存版本与依据。

将经检查与用户确认的定义、实现和验证记录关联至模块版本；发布时冻结相应引用，为后续复用和追溯修订依据提供稳定入口。

CEGIS / 反例引导的语义研究

构建候选，
让反例进入下一轮。

研究借鉴 CEGIS（反例引导归纳综合）的循环思想，将一次研发组织为“构建候选—约束验证—反例反馈—修订复验”：根据当前语义约束提出候选，发现候选与预期含义的偏差后，把反例及触发条件带回下一轮。

每轮核对围绕明确的来源与授权范围展开，重点检查概念边界、适用环境、条件依赖和事件先后。信息可用时点须与求值语境一致；历史行情复核作为另一类研究证据，不以回测表现替代语义一致性。

  1. 01 / CANDIDATE构建语义候选

    依据当前定义与约束提出候选

  2. 02 / VERIFY检查约束与行为

    核对含义、条件及事件顺序

  3. 03 / COUNTEREXAMPLE定位具体反例

    记录偏差及其出现的场景

  4. 04 / REFINE修订并再次检查

    将反馈带回下一轮候选

/ 01

先固定来源与研究问题。

区分来源材料的明确陈述与当前研究解释，整理概念、适用条件和事件关系；先说明候选要回答的问题、可使用的信息及必须遵守的约束。

/ 02

让验证落到具体情形。

围绕候选检查逻辑关系、条件边界与时间顺序，并结合计算工具和历史场景复核。将发现的偏差连同触发情形关联到具体概念或约束，为下一轮修订提供可核对的反例。

/ 03

把修订结果带回研究资产。

依据反例修订相应解释或实现，再复验受影响的约束与既有条件。发布保留用户确认，将采用的定义、代码和验证记录关联到新版本，后续研究从明确的版本依据继续。

WORKSPACE / 工作台与验证入口

从研究问题，
走到可见的复核现场。

研究会话 / 保留上下文

研究对话与结构化研究链并排呈现：对话用于梳理问题与解释，研究链展示当前理解及待确认事项。持续会话接续上下文，使研究者能从已有讨论进入下一轮定义与验证。

计算资产库 / 支持候选实现

指标资产库集中展示工具名称、输入输出与可用状态，帮助研究者选择计算能力；自定义开发与图表审阅入口则将候选实现和观察结果连接起来。

历史复核 / 检查具体场景

通过行情图表、历史回放与本地手动模拟，观察指标在具体走势中的触发时机和状态变化。复核发现的差异可带回语义定义与候选实现，继续核对适用条件、事件先后和解释依据。

ENGINEERING DESIGN / 工程设计与亮点

以语义契约约束生成，
以反例反馈驱动迭代。

/ 01

用语义契约明确模块边界。

以语义契约关联来源依据、概念定义、适用条件和事件关系，明确模块的输入输出与组合边界，使候选实现有共同的核对标准。

/ 02

把验证反馈定位到修订对象。

将验证偏差关联到具体概念、条件或时序关系，区分需要修改的解释与实现。反馈由此转化为可执行的研究动作，每次修订均能回到原始依据核对。

/ 03

以版本关联定义、实现与记录。

发布时冻结模块对应的版本引用，并关联语义定义、实现与验证记录；后续引用保留明确的版本身份，新一轮修订继续记录其来源与依据。

研究方法 / 反例驱动迭代

以来源与语义约束界定研究问题，以反例反馈推动定向修订，再通过版本关联积累可复核的工程资产。

系统设计 / 围绕问题协作

研究会话、计算工具与历史复核服务于个人本地量化研究及按需发起的回测验证，贯通“问题—定义—实现—证据”。项目展示聚焦研究工程，不涉及实盘交易或收益承诺。
